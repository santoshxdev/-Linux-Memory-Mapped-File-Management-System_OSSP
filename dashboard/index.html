System Call Execution Mechanics

open()

Allocates an entry in the process File Descriptor Table, linking to the Kernel Open File Table and physical inode.

mmap()

Creates a new vm_area_struct in the process Virtual Memory Area (VMA) with PROT_READ | PROT_WRITE and MAP_SHARED.

Direct Access

Process dereferences the returned virtual pointer. First access triggers a minor page fault; the kernel maps physical frames via Page Cache.

msync()

Scans dirty page table entries (PTEs) and synchronously writes modified cache blocks to physical disk via MS_SYNC.

munmap()

Tears down the VMA page table entries and releases the virtual address range back to the Linux virtual memory manager.

Project Presentation & Viva Guide

Linux Memory-Mapped File Management System

This project demonstrates high-performance file I/O and virtual memory mapping using the POSIX mmap() family of Linux system calls. Traditional file access with read() and write() involves double-buffering and context switching between user space and kernel space. By mapping a file directly into the calling process's address space, data can be manipulated via standard memory pointers (e.g. memcpy()).

Viva Demonstration Checklist:

  1. Step 1: Open a File — Calls open(O_RDWR) and obtains a valid file descriptor (e.g. FD: 3).
  2. Step 2: Map into Memory — Invokes mmap(NULL, size, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0). Point out the returned virtual address (e.g. 0x7063f004c000) and the entry in /proc/self/maps.
  3. Step 3: Modify Data Directly — Type new text at offset 0 and click "Write Directly to Memory". Note that the write happens via C pointer dereference, and status changes to PENDING (dirty page).
  4. Step 4: Synchronize with msync() — Click "Sync Changes" to invoke msync(MS_SYNC). The kernel flushes dirty pages to disk, and status changes to SYNCED.
  5. Step 5: Unmap and Close — Call munmap() to release the virtual memory area, followed by close() to release the descriptor.
